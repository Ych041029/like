## 二、标准工作流（7步，你当司机）

### 第1步：了解视频基本信息
```
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate -show_entries format=duration -of default=noprint_wrappers=1 "视频路径"
```
记录分辨率、时长。**竖屏游戏（如416×776）字体小，需 scale 3**。

### 第2步：抽几帧样本，OCR 精确定位面板坐标（关键，别用视觉模型猜）
写一个临时探针脚本，对样本帧跑 PaddleOCR，**打印每条文字的精确像素坐标**。要找的3个坐标：
1. **进度行的 cy**（X/Y 格式数字的位置）
2. **任务名行的 cy**（主线任务文字的位置）
3. **经验条的 cy**（顶部另一条 X/Y，必须和任务进度区分）

据此算出 `--panel x,y,w,h`（框住"任务名行+进度行"）和 `--prog-y ymin,ymax`（经验条y范围，排除经验条噪声）。

> ⚠️ **关键：判断任务名在进度的上方还是下方！** 不同游戏布局不同：
> - 多数游戏：任务名在上、进度在下 → 不加 `--task-below`
> - 《神器传说》类：进度在上、任务名在下 → **必须加 `--task-below`**，否则所有任务名都会丢失
> 探针时看清楚任务名行和进度行的 cy 大小关系再决定。

> ⚠️ **面板框左边界别切太右**：短任务左对齐 cx 小，框左边界取 `min(任务名cx) - 30`。

### 第3步：用样本帧验证坐标 + 判断布局（强烈推荐，省2小时）
用样本帧生成 OCR 缓存，**实测** `extract_task_info` 能否提取出任务名。这能提前发现"任务名=None"这类布局问题，避免白跑2小时。

### 第4步：正式跑（scale 3，后台运行，约2~10小时/30分钟视频）
```
python "...游戏任务分析_含漏任务核查.py" "视频路径" --panel x,y,w,h --prog-y ymin,ymax --scale 3 --out "输出目录"
```
若任务名在进度下方，加 `--task-below`。后台运行，完成后读 `主线任务时间线_*.md`。

### 第5步：核对结果 + 错字清洗（用 --reuse-ocr 秒级重跑，不重新OCR）
跑完读 `主线任务时间线_*.md`。如果任务名有 OCR 错字：
1. 写一个错字表文件（每行 `错字=正字`，或 `re:正则=替换`）
2. 用 `--reuse-ocr` 复用缓存秒级重跑清洗：
```
python "...游戏任务分析_含漏任务核查.py" "视频路径" --reuse-ocr "输出目录\ocr_raw.txt" --panel x,y,w,h --prog-y ymin,ymax --fix-typo "错字表.txt" --out "清洗后目录"
```

### 第6步：漏任务核查（本版新增的核心功能，自动执行）
脚本在第5步出表格后会**自动执行漏任务核查**，生成 `候选漏任务清单_视频名.md`：
- 扫描 OCR 数据，找出"读到了任务名、但被规则过滤掉"的任务
- 合并 OCR 错字变体，列出**精准首末时间 + 出现次数**
- ⚠️ **只列清单，不自动加入**——把清单交给用户，用户用时间点核对原视频后决定加哪些

### 第7步：人工核对 + 补漏（你和用户协作）
1. 把 `候选漏任务清单_*.md` 整理给用户
2. 用户拿清单里的时间点去**原视频核对**，确认哪些是真漏了
3. 用户告诉你加哪些 → 你手动补进最终 `.md`：
   - 任务名 + 起止时间照填（来自清单）
   - 进度列填 **"OCR未识别"**（因为这些任务本就是因为没读到进度才漏的）

## 三、所有命令参数速查

| 参数 | 作用 | 何时用 |
|---|---|---|
| `--panel x,y,w,h` | 手动指定面板框 | **必用**，第2步定位后 |
| `--prog-y ymin,ymax` | 经验条y范围（排除经验条） | 有经验条干扰时 |
| `--scale N` | 图片放大倍数（默认2） | 竖屏/小字用3-4 |
| `--task-below` | 任务名在进度【下方】时启用 | 神器传说类布局 |
| `--out 目录` | 输出目录 | 必用 |
| `--fix-typo 文件` | 外部错字表清洗 | 任务名有OCR错字时 |
| `--reuse-ocr 文件` | 复用OCR缓存秒级重跑 | 改逻辑/错字后快速验证 |
| `--audit-min-count N` | 漏任务候选最低出现次数（默认3） | 调漏任务清单噪声 |
| `--no-audit-missed` | 跳过漏任务核查 | 一般不用 |
| `--diagnose` | 只抽帧+OCR不分析 | 诊断OCR效果 |
| `--confirm` | 先回显面板内文字供核对 | 第一次跑核对坐标 |
| `--fps N` | 每秒抽帧数（默认2） | 短任务多可提4 |

## 四、漏任务的两种性质（第7步判断用）

漏任务核查清单里会出现两类，性质不同：

1. **OCR读到名但无进度的任务**（如试炼1-6）：OCR读到了任务名、能定位时间，但全程没读到进度数字 → 时间可信、任务可信，**加进去价值高**。
2. **OCR完全没读到的任务**（如瞬间通关的关卡）：清单里不会有（因为OCR没痕迹），只能靠"关卡编号跳跃"推断（如1-6后直接1-8→推断漏了1-7）→ 纯推断，加进去要标注"推断"。

第6步的自动核查只覆盖第1类。第2类需要你和用户一起靠"编号不连续"去推断。

---

## 五、已知局限（手册第六节，避免重蹈覆辙）

- **OCR读不全长任务名**：scale越大越少，但无法根治
- **OCR读错进度分母**：逻辑救不了OCR数字错误
- **亚秒级任务**：fps=2可能抓不到显示<0.5秒的任务，可提--fps 4
- **处理漏任务不要急着改代码**：先去 ocr_raw.txt 查证OCR读到没有，再用 --reuse-ocr 验证假设
