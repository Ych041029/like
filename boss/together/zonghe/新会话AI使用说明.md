# 新会话 AI 使用说明 — 整合工具 run_all.py（任务1+任务2 一键分析）

> 你（AI）拿到这份说明 + 用户的游戏视频，任务是：用整合工具跑出一份《总报告》。
> 整合工具 = 一条命令依次完成：抽帧一次（两任务共用）→ 任务1（游戏概述/核心循环）→ 任务2（主线任务时间线/漏任务核查）→ 自动汇总总报告。

---

## ⚠️ 第〇节：路径基准声明（先读这段再动手）

**本文档所有路径均为相对路径，基准是 together 文件夹**（下称"根"）。

**开始任何操作前，先向用户确认根的实际位置**（例如 `D:\tools\together`、`C:\Users\xxx\Desktop\together`）——用户首条消息通常会直接给出；没给就问一句。确认后，**执行任何命令前把相对路径拼成绝对路径再执行**（例：`zonghe\run_all.py` → `D:\tools\together\zonghe\run_all.py`）。

目录结构（相对根）：

```

├── videos\      ← 用户把要分析的视频丢这里（输入）

├── GameVideoAnalyzer\game_analyzer.py              ← 任务1（勿改）

```

- ⚠️ 三个脚本按相对位置互相引用，**结构必须完整**，勿拆散改名
- ⚠️ Windows 控制台中文可能乱码：跑命令前先 `chcp 65001`；**看结果必须读 .md 文件，别看控制台**

## 一、环境检查（每台新电脑第一次必做，禁止跳过）

依次执行，**全部正常才继续**：

```
python --version     ← 应显示 Python 3.8~3.10（显示 3.12+ 或"不是内部命令" → 先装 Python 3.10）
ffmpeg -version      ← 应显示版本号（"不是内部命令" → 先装 ffmpeg 并加入 PATH，重开命令行再试）
```

再检查 Python 依赖库：

```
python -c "import paddleocr, numpy, PIL, matplotlib; print('OK')"
```

- 显示 OK → 环境就绪，进入工作流
- ★ **任一项不合格（Python 缺失或版本不对 / ffmpeg 缺失 / 依赖库缺失）→ 按《环境自动安装(AI执行).md》处理**：该文档会指引你自动安装缺失项（winget 装 Python 3.10 / ffmpeg，pip 装依赖库）；自动安装失败再转手动教程（一键安装.bat 仍是依赖库的手动保底方式）
- 首次分析时 PaddleOCR 会自动下载中文识别模型（约100MB，需联网，只下载一次）

## 二、标准工作流（5 步）

### 第 1 步：确认视频（在 videos\ 里）
让用户把视频放进 `videos\`（若还没放）。视频定位规则：
- 传给 run_all.py 的"视频"参数可以是：`videos\` 里的**文件名**（可省略 .mp4 扩展名）或完整路径
- 不确定文件名就列出 `videos\` 目录给用户选
- 然后看视频信息：
```
ffprobe -v error -select_streams v:0 -show_entries stream=width,height -show_entries format=duration -of default=noprint_wrappers=1 "根\videos\视频文件名"
```
记录分辨率、时长。**竖屏游戏（宽<500）字体小 → --scale 3**。

### 第 2 步：确定面板参数（新游戏必做；已知游戏直接跳到第3步用第四节参数表）
均匀抽 3-5 张样本帧（`ffmpeg -ss 秒数 -i "视频" -frames:v 1 样本.jpg`），
你用视觉看图，找到画面中【主线任务面板】的位置，确定三个信息：
1. 进度行（X/Y 格式数字）的位置
2. 任务名行（任务文字）的位置
3. 任务名在进度的**上方**还是**下方**（下方 → 必须加 `--task-below`，否则任务名全丢）

→ 算出 `--panel x,y,w,h`（框住"任务名行+进度行"两行；左边界 = 任务名最小 cx − 30，别切太右）。

### 第 3 步：正式运行（长视频 2-10 小时，务必后台/detached 跑）
```
python "根\zonghe\run_all.py" "视频名" --panel x,y,w,h --task-below --scale 3
```
- **不用传 --out**：报告自动输出到 `reports\视频名\`
- 30 分钟视频：抽帧约几分钟，任务1约几分钟，**任务2全帧OCR约2-10小时**
- 建议用 detached 方式启动，防会话断掉：
  `start /b cmd /c "python 上面完整命令（路径全部拼成绝对）> 根\reports\run.log 2>&1"`
  然后定期查看 `run.log` 末尾（出现 `✅ 总报告 ->` 即完成）
- 期间用户问进度 → 读日志最后几行汇报

### 第 4 步：完成后检查《总报告_视频名.md》（位置固定：reports\视频名\）
该目录应有：`总报告_视频名.md`（⭐重点）+ 任务1报告/环形图 + 任务2时间线/漏任务清单 + ocr_raw.txt 等。
检查两点：
1. **任务名有 OCR 错字？** → 写错字表文件（每行 `错字=正字`），用任务2秒级重洗（不重新OCR）：
   ```
   python "根\分析视频工具\游戏任务分析_含漏任务核查.py" "根\videos\视频文件名" --reuse-ocr "根\reports\视频名\ocr_raw.txt" --panel 同参数 --task-below --fix-typo "错字表.txt" --out "根\reports\视频名_清洗后"
   ```
2. **候选漏任务清单**有内容 → 整理成列表交给用户，用户拿时间点核对原视频后决定补哪些。

### 第 5 步：向用户汇报
把总报告三部分的要点总结给用户：
- 第一部分：游戏类型/核心循环/机制（任务1）
- 第二部分：主线任务时间线表（任务2）
- 第三部分：漏任务候选，等用户确认

## 三、run_all.py 参数速查

| 参数 | 作用 |
|------|------|
| 视频名或路径 | `videos\` 里的文件名（可省略扩展名），或视频完整路径 |
| `--panel x,y,w,h` | 任务面板坐标（新游戏第2步定位后传） |
| `--task-below` | 任务名在进度数字**下方**时加（如神器传说） |
| `--scale N` | 任务2 OCR放大倍数，竖屏小字用 3（默认2） |
| `--prog-y y1,y2` | 经验条y范围（有经验条干扰时排除，可选） |
| `--fps N` | 抽帧率，默认2=一秒两帧 |
| `--out 目录` | 输出目录（**默认 reports\视频名\，一般不用传**） |

## 五、耗时与注意事项

- 抽帧和任务1总共约 5-10 分钟；任务2是瓶颈（全帧OCR带坐标）
- 任务1失败不影响任务2（run_all 会继续跑并记录 task1_run.log）
- 机器 CPU 被限速时整体会更慢，属正常，耐心等日志出现完成标记
- 结果固定在 `reports\视频名\`；`总报告_视频名.md` 是最终交付物
