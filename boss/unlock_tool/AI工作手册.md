# AI 工作手册 · 解锁时间线工具

> 本文档写给操作本工具的 AI 助手。你（AI）将代替人类完成视频分析的机器执行、
> 证据核验与命名终审。人类只负责两件事：拖框标定（需要鼠标）和最终验收报告。

## 0. 你的职责边界

| 环节 | 谁做 | 说明 |
|---|---|---|
| 拖框标定 | **人类** | GUI 需要鼠标操作。你负责启动 calibrate.py 并口头引导 |
| 检测流水线 | 机器 | analyze.py 自动完成，你负责执行命令与读取结果 |
| 证据核验+命名 | **你（AI）** | 逐条查看 ev 证据图，确认变化真实性并命名（见第4节判定规则） |
| 出正式报告 | 机器 | finalize.py，你负责先填好 names.json |

## 2. 标准作业流程（新视频）

```
⓪ 环境准备（新机器首次，AI 自行完成，无需人类）：
   python check_env.py 自检；缺 opencv/numpy → pip install opencv-python numpy
   （装正式版勿 headless）；缺 ffmpeg → winget install Gyan.FFmpeg
   或官网下包把 bin 加入 PATH。

⓪A AI 自动标定（v2.2 新增，可替代人工拖框；人工只做确认，AI 不擅作主张）：
   1. 选帧：review_kit\pick_tail_frames.py 从视频尾部抽候选帧，AI 逐张目检；
      结尾无干净帧（战斗/弹窗）时扩大时间窗向前找，直到"面板完整、无弹窗"，
      不许拿战斗帧凑合；
   2. 提案：AI 目视识别三类面板，自行衡量框的数量/大小/粒度/是否避让动画区，
      用 review_kit\render_boxes.py 渲染提案图；精确定位必须用
      review_kit\grid_overlay.py（20px 网格坐标尺）或颜色检测
      （inRange 找红点角标/橙色图标），禁止纯肉眼估读；
   3. 逐类确认（顺序：礼包面板 → 副本面板 → 养成系统面板，
      每类独立渲染、独立询问，禁止把多类挤在一张图里一次确认）：
      - 渲染图路径明确告知人类（弹窗不可靠必须给路径），询问位置是否正确；
      - 正确 → 下一类；不正确 → AI 渲染 A/B/C 候选方案供人类选择，
        或按人类文字描述修正后重渲染再确认；
      - 未获人类明确确认前，禁止写入 config.json、禁止开始分析；
   4. 三类全部确认后：写 config.json（养成系统面板写入 cultivation.style
      与 slots），按 ③ 继续。
   5. 养成系统面板样式（每游戏固定一种，不得中途改判）：
      灰色锁定→彩色点亮 = gray2color（同副本面板解锁方式与阈值）；
      空剪影→首次填入 = firstfill（首填语义，阈值较严，换装/升级不记）。
      AI 依据干净帧形态（灰牌/锁徽 vs 空剪影+名称）提出判断——样式属游戏
      语义知识，必须经人工确认后写入 config 的 cultivation.style。

① 每次分析前必须人工确认拖框（2026-09-02 升级：无条件，每视频每跑必走）
   不管 config.json 是否已存在、不管是否同个游戏、不管之前签过多少次——
   只要用本工具分析视频，就必须先渲染三类框的提案图给人类过目签字，
   人类回一句"没问题"后才能进入分析。没有例外，没有豁免。
   ├─ config.json 已存在 → 用已有 rois 渲染提案图（render_boxes.py），
   │   按礼包面板 → 副本面板 → 养成系统面板 顺序逐类询问签字；
   ├─ config.json 不存在 → 先做标定（见第3节），渲染提案图逐类签字；
   └─ 全部签字后 → 写入 calib_note（记录本日签字），再做 ③。
   背景与教训：跳过这一步会导致 AI 凭已有 config 静默跑分析，
   而标定的框位/语义可能与当前视频实际不符（图标可能已移动/新增/消失），
   人类过目是最后兜底——跳过=放弃兜底，不可接受。

①A 复用配置的逐类确认（与①合并，不再单独设触发条件）
   原按触发条件跳过的设计（2026-08-31 版）已废弃，
   统一走①的"每次必确认"流程——无例外。

确认后 AI 在 calib_note 追加一行：日期 + "人类签字确认" + 视频
② 【仅首次】标定帧时刻必须先问人类：
   明确询问："请提供用于标定的干净帧时间点（视频第几分几秒），或直接给我一张
   截图。" 干净帧=面板完整、无弹窗遮挡、结构最清晰的画面，通常在视频末段。
   人类答复后才执行（示例）：
   python calibrate.py "<视频路径>" 6:40
   禁止在未询问的情况下使用无参数模式（那会自动取中点帧兜底，仅限人类明确
   说"你自己选"时使用）。

③ python analyze.py "<视频路径>" games/<游戏名>
   视频按约定放 videos\ 下（如 videos\7分钟灵画.mp4），命令在工具根目录执行；
   finalize 出报告时会自动发布到 reports\<游戏名>\（固定交付位置）。
   正常 2~5 分钟。需要最高精度加 --fps 30（慢15倍，产物在 work_f30）。

④ 证据核验（你的核心工作，见第4节判定规则）：
   读 games/<游戏>/work/timeline.json，
   对礼包（band）/副本（nav）/养成（cultf、cultg）事件逐条核验。

⑤ 编辑 games/<游戏>/names.json（格式见第5节）与 review_notes.md（终审备注，
   finalize 会自动拼接到报告尾部）后运行：
   python finalize.py games/<游戏名>
   会自动附带：压线事件清单 + 首末对拍审计（"变了但账上没事件"的疑似漏检，
   须目检 work/review/audit_start_vs_end.png 裁决，见第9节）。
   生成 解锁时间线.md，向人类报告结果并附证据文件路径。
```

## 3. 拖框标定要点（引导人类时转述）

- **标定帧由人类定（推荐人类自己截图）**：末尾不必然干净——可能正处战斗/弹窗，
  "哪一帧面板最完整"是人看一眼就知道的空间判断。优先让人类在播放器里暂停
  截图，然后 `python calibrate.py "截图.png" "视频.mp4"`（第二参数做分辨率
  对齐，不一致自动缩放；截图须为原图勿预画框、勿带播放器控件，并让人类
  告知大致时间点记入 config）。人类不想截图时给时间点：
  `python calibrate.py "视频.mp4" 6:40`；工具自动选帧仅为人类授权后的兜底；
- 三类顺序无关：【礼包面板】图标各 1 框 → 【副本面板】逐个小图标各 1 框 →
  【养成系统面板】逐槽 1 框（并判定样式 gray2color/firstfill，经人工确认后
  写入 config 的 cultivation.style 与 slots，见⓪A第5步）；
- 每类可画多个框（如左右两列图标）；框画歪按 ESC 放弃重来；
- 结束后必须目视核对 crop_*.png 内容与人类口述的类别一致。

## 4. 证据核验判定规则（核心！逐条执行）

对 timeline.json 中每个事件，打开对应的 `ev/<id>_fXXXXX_b.png`（前）与
`_a.png`(后) 对照判断：

| 前/后帧内容 | 判定 |
|---|---|
| 前=空剪影/灰色 → 后=彩色内容或点亮图标 | ✅ **真解锁/首次填入**，采信 |
| 前=已有内容 → 后=另一外观或Lv变化 | 换装/升级，**不记**（不计入解锁） |
| 前=彩色 → 后=灰色 | 反向变化，单独列出提示人类（如活动结束） |
| 前后内容相同，仅亮度/色调不同 | ⚠️ 光照/遮挡伪影，**丢弃** |
| 前后都是动画中间态（光效、飘字） | ⚠️ 特效噪声，**丢弃** |
| mode=reveal 且 gap 跨战斗 | 通常是"重见主页"恢复事件：对照 a 帧与更早基线，无实质变化则丢弃 |

**铁律（来自实战教训，违反即出错）：**
1. **绝不把首个事件直接当首填时刻**。启动初期（前 8 秒）有初始化瞬态已被标记
   `init_transient`，直接跳过；8 秒后仍可能是开箱光效扫过（本样例中武器格的
   机器候选 00:13 是假的，真值 01:43.73 在后续簇里）。
2. **命名前必须亲眼看证据图**。文字描述/数值再合理也算未核验。
3. 拿不准的时刻，用 `densify.py` 精化（见第6节）或对嫌疑窗口做切片目检。
4. 横幅带（band）的闲置闪光动画会造成假"登场"事件：核对 a 帧里图标数量/排布
   是否真的增加了；必要时用 densify 双参照精化入场时刻。
5. 同一 id 的多条事件按时间排序组成状态链，"首填"=第一条通过上述判定的
   空→有事件；若第一条事件前帧里图标/内容已存在，说明开场已持有，标注"开场已持有"。

## 5. names.json 格式与 finalize

```json
{
  "ACT_新手礼包": {"name": "新手礼包入口登场", "time": "00:26", "note": "可选备注"},
  "主线": {"name": "主线入口解锁", "time": "01:03", "note": "之后点亮为瞬态不计"},
  "法相": "法相（未解锁）"
}
```
- 字符串 = 仅命名；对象 = 命名 + 人工确认时刻（会覆盖机器候选值加粗显示）；
- 没写 names.json 或缺 id 时 finalize 显示"待审"，不算完成；
- 运行 `python finalize.py games/<游戏名>` 生成 `解锁时间线.md`。

## 6. densify.py 精化用法

嫌疑窗口（已知 时刻A前是旧状态、时刻B后是新状态）内精确到 0.01 秒：

```python
from densify import densify2
r = densify2(video路径, (x,y,w,h), t_lo秒, t_hi秒, 参照B图, 参照A图)
# r["t"] = 精确时刻(秒)。原理：窗口内30fps逐帧与两张参照图比相似度，
# 阴影/压暗帧两边都不像会被自动跳过。
```
参照图直接用 timeline 里该事件的 ev _b/_a 读取即可。窗口越贴近真实过渡越准，
建议 ≤12 秒。brightness_gate=True 可叠加亮度过滤（严格但可能漏检，默认关）。

## 7. 已知陷阱清单（全部来自真实翻车记录）

1. **opencv 无窗口**：报 `function is not implemented` 是机器装了 headless 版
   覆盖了 GUI 版。处理：`pip uninstall -y opencv-python opencv-contrib-python
   opencv-python-headless` 后重装单个 `opencv-python`（注意本机 PaddleOCR
   依赖 ≤4.6 的旧约束）。
2. **cmd 不支持多行 `python -c "..."`**：静默失败无输出。复杂逻辑一律写成
   .py 文件再运行。
3. **python 输出重定向到文件时块缓冲**：后台任务日志看不到 print 不代表卡死，
   以产物文件和进程存活为准。
4. **抽帧按帧率分目录**：work\frames 与 work_f30\frames 独立，换档不混用。
5. **软候选/携带的假阳性**：过渡帧噪声也会登记"待定样子"，携带必须经
   挂起确认（连续 persist 帧仍是新态）+ AI 终审双重过滤；新面孔登记可能被
   空场景假面孔污染（灵画师新手礼包 00:30 案例），AI 终审须对照人工基线
   推翻机器身份标注。
6. **时间轴双轨制（需与人类确认）**：工具测的是"图标出现在屏幕上"的时刻；
   若游戏存在"先满足条件、延迟弹图标"机制，需人类提供官方解锁条件后加
   条件时刻列。
7. **"已人工确认"必须逐字核对范围**：calib_note 里人工确认的可能只是框的几何
   位置/数量，AI 的事后重分类不在其内（灵画师事故正是略读了一行 calib_note
   导致）。AI 改动任何框的类别归类，必须在 calib_note 打 `[AI改·未确认]`
   标记，人工签字后改为 `[AI改·YYYY-MM-DD已确认]`；复用配置前先搜这个
   标记，见到未确认标记就走①A，不得静默复用。标记用固定格式就是为了
   能检索——散在长文本里的说明会被后来的会话略读。
8. **cmd 不支持多行 `python -c "..."` 的补充**：单行 `python -c` 里含换行、
   复杂引号同样会静默失败或产出空文件，且 `&&` 链中前段失败后段的报错
   可能被吞。凡是超过一行的内联代码，一律写 .py 文件再运行（本条与第 2 条
   合并记忆：内联代码只允许真正的一行简单语句）。

## 9. v2 修订（灵画师 7分钟视频 复盘，2026-08-28）

### 9.1 主页带动画的游戏必须加 gate_roi
主页有挂机战斗/飘字/角色走动时，整帧哈希永远对不上基准 → 97% 时间被误判
为非主页（首跑翻车）。解决：config 加 `"gate_roi": [x,y,w,h]`（选一块只在
主页出现且稳定的区域，如底部等级条+装备格），场景门控只比这块。
不配 gate_roi 则维持旧行为（mad_knights 不受影响）。

### 9.2 弱信号解锁（小图标变色/锁徽章消失）是已知盲区 → 首末对拍审计必做
洞府式解锁（68px 图标"白锁消失+棕→青绿"）变化量 ≈h13/Δs±1，压线或低于
导航阈值 → 机器漏报；且 AI 批量审缩略图也会看走眼。对策（已实现
`lock_audit.py <游戏目录>`，finalize 出报告时自动调用，也可手动重跑）：
- 原理：主页首帧与主页末帧给每个追踪区各拍一张，首末对拍——不依赖中间
  有没有报警，"变了但账上没事件"的就是漏检嫌疑；
- 三个指标：结构 ham、饱和度差、**色相直方图相关性**（棕→青绿这类纯变色
  只有色相能抓住，洞府 0.84 vs 未解锁者 0.9+）；指标只做提示，最终以
  audit_start_vs_end.png 对照图目检裁决；
- config 的 audit_alias 登记语义化改名后的 id 覆盖关系。
工具升级候选：把色相距离加进 analyze 主指标（先在 mad_knights 上回归，
确认不引入误报再上）。

### 9.3 densify 双口径：t=停稳时刻，t_first=出现时刻
densify2 现在同时返回 `t`（连续0.4s稳定的停稳时刻）和 `t_first`（最终
A 段内最后一个 B 之后的第一帧 ≈ 开始出现时刻）。**报告表格一律用出现
时刻**（遮挡期解锁=重见后第一干净帧；带入场动画的图标用 t_first），
停稳时刻只进备注。
若 `t_first` 为 None：窗口起点就已经是新状态 → 窗口设晚或参照选错，
必须重设窗口/参照重跑（"活动 04:40 假值"即是此错的变体）。

### 9.4 AI 审图纪律
缩略对照表只做初筛。小图标上**压线事件（ham 距阈值 ±3 以内或 |Δsat|<5）
必须放大到原生分辨率单独裁决**，禁止在缩略表上直接定丢弃。

### 9.8 v2.5（2026-09-02，应人类提案新增：短遮挡重见 nav 强制对比）

**背景案例（灵画师 15分钟视频）**：挑战入口 11:4x 解锁（同屏"恭喜获得"领奖浮层），
玩家随即点击进入副本，点击动画逐帧变化>10bit，persist(3帧)确认窗被持续重置，
事件被推迟到 12:30 重见帧才入账；若重见后不再回主页则为观测盲窗。
长遮挡 force 通道（≥3s）抓到了 12:30，但 11:4x 的首现时刻丢失。

**机制**：`params.short_gap_force`（**默认关**，人工确认后按游戏开启）。
开启后，非主页 **1~5 帧（2fps 下即 ≤2.5s）** 恢复主页时，**副本面板（nav）** 图标
立即与遮挡前最后主页帧对比（即当前 base，遮挡期间不更新），幅度超阈值
（thH=13 / thS=18，同 nav 常规阈值）即**立即入账**（mode=direct、short_gap=1 标记、
附前后帧证据），不等 persist。与长遮挡 force 通道同置信度：强信号直接目击，
证据图供 AI 终审兜底。

**实测依据（灵画师 15分钟，97 处短遮挡重见 × 4 图标 = 388 对比点）**：
- 零阈值"有变化即入账"：324/388（84%）为压缩噪声/滑切抖动（自然抖动 ham 2~7、
  |dS| 5~14），**不可行**——故本机制沿用 nav 真阈值；
- 超真阈值的仅 1 条 = 挑战解锁本身（帧01404，ham=21，遮挡1帧），零误报；
- 超软线（6/8）36 条多为滑切伪影，不在本机制入账范围（低于阈值部分仍由
  carry_candidate 软候选+终审兜底）。

**边界与注意**：
- 仅 nav 生效（用户规格）；礼包/养成面板如需同类通道，先回归再放开；
- 有挂起(pend)的追踪不触发本通道，避免与 v2.3 携带机制双重入账；
- 立即入账不做站稳确认——"解锁即点击进入"场景的动画恰恰会破坏站稳判定，
  这是本机制与常规 persist 的本质差异，也是它存在的理由；
- **改动检测逻辑：mad_knights 回归样例到位后必须补跑**（§8，当前样例已删）；
  灵画师 15分钟视频已做自回归：9 条终审事件完全复现，挑战原生入账 11:4x，
  其余事件与时长不增不减。

### 9.9.1 flymenu_scan.py 通用清点器（游戏无关版，2026-09-02）

`python flymenu_scan.py <视频> <游戏目录> [th=0.85]`——换游戏只需重做标定，
脚本本身零改动。前置三件套（每游戏一次性，约半天）：
1. config.json 的 gate_roi+anchors（解锁时间线任务顺带完成）；
2. flymenu_tpl/ 菜单模板：AI 目检确认菜单后剪图，**同一菜单的不同 UI 状态
   （红点/无红点、滚动位置）各存一张**，命名 `<菜单组>_<状态>.png`（同组=同种
   菜单，分析时人工合并同组区间）；可用 index.json 按模板给 box（位置过滤
   假阳性）与 th；
3. 阈值实测：flymenu.py --calib 看分布定 D_th/occ/min_blocks；模板真命中带
   以实测定（灵画师：A 真命中 0.88~1.00、假阳性 ≤0.85，B 真命中 0.93~1.00、
   假阳性 ≤0.85，分界干净）。
机制：全帧扫描（**含门控拒绝帧**——菜单压暗主页时门控会误拒，14:3x 案例的
教训）、半尺度匹配提速、逐帧开/关状态序列、上升沿计数=点击次数、片尾状态
检查（片尾仍展开的菜单必须被记录）。
已知边界：外观相似的面板（如某面板的深色标签列 vs 菜单条目列）会产生假阳性，
须 AI 目检定性；寿命<0.5s 的菜单需 30fps；全新菜单种类首次出现需目检认识。
灵画师 15分钟视频回归：全帧扫描结果与人类标准答案一致（明细归档于基准包）。

**配套工具与标准流程（2026-09-02 定案）**：
- `flymenu_scan.py <视频> <游戏目录>`：通用清点器（读 flymenu_tpl/ 模板，全帧扫描）；
- `render_clean.py <游戏目录>`：把终审事件+菜单打开区间+菜单文字对照表
  （flymenu_tpl/menu_content.json，AI 目检后填写一次）+ 观测说明.md 渲染成
  干净版《解锁时间线.md》；
- 标准顺序：**finalize → flymenu_scan → AI 目检修约（剔除相似面板假阳性、
  合并门控碎片、填 menu_content 与观测说明）→ render_clean → 人工精校覆盖**。
  注意 finalize 会重写解锁时间线.md，故 render_clean/精校必须在 finalize 之后；
- 游戏无关性：主链路（脉冲找菜单）与三条规则（上升沿计数、片尾状态检查、
  拒绝帧复扫）不依赖点击特效；锚定优先级=光标跟踪＞最近图标推断＋目检＞
  该游戏点击签名（如灵画师金圈，按校准流程实测一次）。

**滑轨归因检查（每游戏终审必做，2026-09-02 教训）**：
部分游戏的入口栏为滑动重排式——新图标从底部/边缘滑入，把已有图标向上/向旁
顶移。这导致：
1. 同一图标的登场事件可能记在不同框位 id 下（滑入时在 A 框，重排后到了 B 框）；
2. 渲染层按框位查事件会漏判——框位无事件 ≠ 图标未登场。
AI 终审必须做以下检查：
  a) 逐对排查：相邻框位在相同时段出现"空→有"配"有→空"的成对事件，
     → 可能是同一图标在滑动，非两次独立事件；
  b) 用帧裁图逐帧目检：确认图标从哪个框位滑入、最终停在哪；
  c) 终审后在 icon_status.json 写入每图标的最终解锁状态与实际归属，
     渲染器据此生成正确报告，不再按框位自行推断；
  d) 报告中不使用"未解锁"描述已实际登场的图标——只描述真正带锁/未出现的。
灵画师教训：活动菜单被误锚到玩法入口（凭位置推断）、福利/新手礼包被误标
"未解锁"（事件记在滑入时的旧框位名下，渲染器按框位查不到）——均已纠正。
- 报告章节随之重排：一礼包面板 / 二副本面板 / 三养成系统面板 /
  四战斗时段 / 五疑似弹窗时段（未解锁仍逐行分列，见 9.6③）。


**三件套硬规格（发现异常时的必做三步，不得跳过、不得降级）**：
1. **起疑**：strip_sample/逐秒条带（原生分辨率）——缩略图不够看就用原生分辨率
   逐秒条带排查，不许在缩略图上直接下结论；
2. **钉秒**：densify2 精确到 0.01 秒——拿不准的时刻必须钉秒，不许用
   2fps 粒度值凑合；
3. **取证**：证据裁图换原生分辨率——缩略图/缩放裁图不能作为终版证据，
   证据必须是"菜单确实在场"的那一帧的原生分辨率裁图。
