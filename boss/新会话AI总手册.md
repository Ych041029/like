# 新会话 AI 总手册 — boss 游戏分析总工具（together + unlock_tool）

> 你（AI）拿到这份手册，任务是按用户需求调度两路分析工具，最终产出一份《游戏分析总报告》。
> **两路工具都是独立成熟的工具，你只调度和汇总，不要改它们的内部代码。**

---

## ⚠️ 第〇节：路径基准声明（先读）

**本文档所有相对路径基于 boss 文件夹**（下称"根"）。开始前先向用户确认根的实际位置（用户首条消息通常会给；没给就问一句），**执行命令前一律把相对路径拼成绝对路径**。

```
boss\                              ← 根
├── videos\                        ← ★【视频统一丢这里，两路工具共用同一个视频】
├── together\                      ← 工具1：玩法/任务分析（三合一套件）
│   ├── reports\<视频名>\          ← 工具1报告输出
│   └── zonghe\run_all.py          ← 工具1入口（细节读 together\zonghe\新会话AI使用说明.md）
├── unlock_tool\                   ← 工具2：系统解锁时间线
│   ├── games\<游戏名>\            ← 工具2的标定/证据/最终交付物
│   ├── reports\<游戏名>\          ← 工具2报告发布位置
│   └── AI工作手册.md              ← 工具2操作SOP（细节读它）
├── merge_report.py                ← ★ 总汇总脚本（两路结果→一份大报告）
└── reports\<名>\游戏分析总报告_<名>.md   ← ★ 最终交付物
```

---

## 一、需求路由（用户要什么 → 走哪路）

| 用户想要 | 走哪路 | 操作 |
|----------|--------|------|
| 游戏怎么玩 / 概述 / 核心循环 / 任务时间线 | **只跑工具1** | 读 `together\zonghe\新会话AI使用说明.md` 按其工作流执行 |
| 哪个功能什么时间解锁（面板图标变亮时刻） | **只跑工具2** | 读 `unlock_tool\AI工作手册.md` 按其 SOP 执行 |
| **都要（默认推荐）** | **两路都跑，最后合并** | 先跑工具1（全自动）→ 再陪用户走工具2（含人工环节）→ 跑 merge_report.py |

---

## 二、环境（两工具共用，一次装好）

- Python 3.10（禁止更高版本）+ ffmpeg，检查方法与自动安装见 `together\zonghe\环境自动安装(AI执行).md`
- 依赖库合并清单（装在一起即可，互不冲突）：
  ```
  paddlepaddle / paddleocr / numpy<2 / Pillow / matplotlib     ← 工具1用
  opencv-python==4.6.0.66                                      ← 两边共用的关键锁定项
  ```
- ⚠️ **opencv 必须锁 4.6.0.66 正式版**（带GUI，勿装 headless 顶替、勿升级）：
  - 工具1的 PaddleOCR 要求 opencv≤4.6；工具2的拖框标定需要带GUI正式版——**4.6.0.66 是唯一同时满足两边的版本**
- 环境自检：`python unlock_tool\check_env.py`（工具2自带）+ 工具1的三项检查

## 三、"都要"标准流程（推荐主流程）

### 第1步：视频就位
让用户把视频丢进 `根\videos\`（**总工具统一视频入口，两路工具共用同一个视频**）。记录视频名。

### 第2步：跑工具1（全自动，先跑因为快）
按 `together\zonghe\新会话AI使用说明.md` 工作流：面板定位（已知游戏查参数表）→ 后台跑 run_all.py
→ 产出 `together\reports\<视频名>\总报告_<视频名>.md`（30分钟视频约2-10小时，挂着等）。

### 第3步：跑工具2（含人工环节，与用户协作）
按 `unlock_tool\AI工作手册.md` SOP：
1. **标定**（每游戏一次，需要用户拖框参与）：`python calibrate.py "<根>\videos\<视频文件>" <mm:ss>`
2. **分析**：`python analyze.py "<根>\videos\<视频文件>" "<根>\unlock_tool\games\<游戏名>"`
   （视频用完整路径指向 根\videos\ 里的文件，与工具1共用同一个视频源）
3. **证据核验+终审**（AI逐条判定，规则见其手册第4节，需用户确认）
4. **finalize 出报告**：自动发布到 `unlock_tool\reports\<游戏名>\解锁时间线.md`

### 第4步：总合并
两路都完成后：
```
python "<根>\merge_report.py" <名> [--video-name <视频名>] [--game-name <游戏名>]
```
- 视频名=游戏名时只填 `<名>`；不一致时用参数分别指定
- 产出 **`<根>\reports\<名>\游戏分析总报告_<名>.md`** ⭐ 最终交付物
  （第一~三部分=玩法/任务，第四部分=解锁时间线，附录=产物索引）
- 只跑完一路也可以先合并（另一路会标注"未产出"，之后重跑合并即可补全）

### 第5步：向用户汇报
把总报告四部分要点总结给用户；两路各自的"漏任务清单/审计压线事件"待确认项一并列出。

---

## 四、注意事项

- **不要修改两路工具的任何内部文件**；调度层只有 merge_report.py 和本文档
- 工具2的标定/终审必须用户参与（拖框、看证据图确认），不要试图全自动绕过
- 长任务挂后台时提醒用户别关会话/电脑；进度看各自日志
- Windows 控制台乱码：先 `chcp 65001`；**看结果读 .md 文件**
- 转发整套给别人：整个 boss 文件夹打包（videos/reports/games 里的个人数据可先清）
