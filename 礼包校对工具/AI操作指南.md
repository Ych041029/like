## 用户会提供的信息

用户每次校对新活动时，会提供：

1. **策划表格**（照片/截图/Excel）—— 包含每档礼包的奖励内容
2. **活动ID**（数字，如 76=端午活动，80=夏日活动）—— 用于Unity脚本和配置文件
3. **物品ID**（可选）—— 用于确认物品名称

## AI 执行流程（5步）

### 第1步：识别策划表格

用户会发来策划表格的照片/截图。AI需要：

1. 读取图片，提取每档礼包数据：
   - 序号（1, 2, 3...）
   - 礼包类型（免费 / 广告*1 / 钻石*600 / 30元 / 68元 / 128元...）
   - 奖励内容（物品名*数量，多个用+连接）
   - 限购信息（每日限购1次 / 永久限购3次 / 不限购等）

2. 转换为标准格式：
   ```
   弹药*100（日购*1）
   夏卷*1（日购*1）
   夏卷*2+弹药*50+秒表*5（日购*1）
   夏卷*10+钻石*300（日购*1）
   ```

3. 注意策划简称，需后续做名称映射：
   - 夏卷 → 夏日冰棒
   - 秒表 → 加速秒表
   - 签到引擎 → 浮浪小鸭
   - 其他简称根据上下文判断

### 第2步：写入配置文件 peizhi.xlsx

用 Python + openpyxl 写入 `config\peizhi.xlsx`，包含3个sheet：

**Sheet 1「活动配置」**：
| 参数 | 值 |
|---|---|
| 活动名称 | （从策划表提取）|
| 活动ID | （用户提供）|
| 礼包子活动索引 | 1 |

**Sheet 2「策划标准」**：
| 序号 | 礼包类型 | 策划标准（奖励内容+限购）|
|---|---|---|
| 1 | 免费 | 弹药*100（日购*1）|
| 2 | 广告*1 | 夏卷*1（日购*1）|
| ... | ... | ... |

**Sheet 3「名称映射」**：
| 策划简称 | 游戏全称 |
|---|---|
| 夏卷 | 夏日冰棒 |
| 秒表 | 加速秒表 |
| 签到引擎 | 浮浪小鸭 |

> 如果 peizhi.xlsx 不存在，可运行 `python scripts\make_template.py` 生成模板后再填写。

### 第3步：指导用户在Unity中导出数据

告诉用户：

1. 打开 Unity 项目 `MergeGame_Android`
2. 确认 Game 对象上已挂载 `ProofBuyExporter` 组件
3. 确认 Inspector 里 `Activity Id` 填了正确的活动ID
4. 点击播放按钮运行游戏
5. 进入游戏后，打开要校对的**活动礼包界面**（必须能看到礼包页面）
6. 按以下任一方式触发导出：
   - 按 **` 键**（反引号，键盘左上角 Esc 下方）
   - 按 **F5 键**
   - 按 **F12** 打开GM菜单 → 点击 **"▶ 一键校对购买"**
7. 等待 Console 依次显示：
   - `第1步：导出配置表数据` → 导出 packages.json
   - `第2步：开始自动购买记录真实到账` → 逐档自动购买
   - `全部完成 成功购买: N` → 两个数据文件已生成
8. 用户确认完成后，进入下一步

> **关键**：按触发键之前，必须已在游戏中打开活动礼包界面，否则导不出数据。

### 第4步：运行校对脚本

方式一（推荐，一键运行）：
```cmd
cd /d "d:\ych\公司游戏备份\礼包校对工具"
run.bat
```

方式二（命令行）：
```cmd
cd /d "d:\ych\公司游戏备份\礼包校对工具\scripts"
python proofread.py --output "d:\ych\公司游戏备份\礼包校对工具\output\校对结果.xlsx"
```

### 第5步：汇报结果

读取校对脚本输出，向用户汇报：
- 总档数、一致数、不一致数
- 列出有误的档位及具体差异
- Excel文件已保存到 output 目录

## Unity 脚本说明

工具只有一个 Unity 脚本：`ProofBuyExporter.cs`（合并版）

**功能**：一次按键同时导出三种数据
1. 配置表数据 (packages.json) → 礼包页面 + 领取页面
2. 真实购买数据 (packages_real.json) → 到账页面

**支持的礼包类型**：
- 免费档：直接购买
- 广告档：编辑器中自动跳过广告直接购买
- 钻石消耗档：直接购买
- 人民币付费档：自动确认代币弹窗（需测试服/BUSINESS模式）

**Inspector 参数**：
| 参数 | 说明 | 默认值 |
|------|------|--------|
| Activity Id | 活动ID（每次校对不同活动必须改） | 80 |
| Shop Sub Index | 礼包子活动索引 | 1 |
| Config Export Path | 配置表导出路径 | output\packages.json |
| Real Export Path | 真实到账导出路径 | output\packages_real.json |
| Wait After Buy | 购买后等待时间（秒） | 3.0 |
| Buy Timeout | 购买超时时间（秒） | 8.0 |
| Skip Paid Packages | 是否跳过人民币付费档 | false |

## 校对结果各列含义

| 列 | 名称 | 数据来源 | 比对方式 |
|---|---|---|---|
| A | 序号 | 配置文件 | - |
| B | 礼包类型 | 配置文件 | - |
| C | 策划标准 | 校对员填写 | 基准 |
| D | 礼包页面 | Unity配置表 | 完全匹配C列 |
| E | 领取页面 | Unity配置表（去限购）| 完全匹配C列 |
| F | 到账页面 | 真实购买背包差值 | 子集匹配C列 |
| G | 正误 | 自动判断 | 正/有误/跳过 |

## 关键注意事项

1. **档数不固定**：策划表有几档就填几档，2-9档都支持
2. **序号连续**：从1开始连续编号，不要跳号
3. **名称映射**：策划简称必须映射为游戏全称，否则比对会误报
4. **真实到账子集匹配**：付费档真实到账会包含累充道具（港币/台币累充等），这些是充值系统附带的，不算错误
5. **广告档**：Unity编辑器中自动跳过广告播放，直接触发购买
6. **付费档**：需要测试服（BUSINESS模式）环境，否则无法自动确认代币弹窗
7. **输出路径**：默认输出到 output\校对结果.xlsx，可用 `--output` 参数指定
